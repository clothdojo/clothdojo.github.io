02 / BUILT TO GENERATE AGAIN

From a collection
to a repeatable process.

New policy rollouts create new physical trajectories. Re-rendering saved motion creates new observations. ClothDojo separates these operations so the data can keep evolving.

01Vary the starting point.

Choose a garment and initial configuration. The asset pool contains 500 garments; current generated training sets cover 400 for flattening and 399 for folding.

02Generate new motion.

Execute the learned policy in closed loop. Apply task-specific success criteria and retain successful trajectories. Another run from new states adds new manipulation experience.

Generation workflow ↗
03Re-render observations.

Replay recorded physical motion with different garment materials, surfaces, lighting and backgrounds, then export RGB training episodes. Visual changes do not create a new physical execution.

RGB export workflow ↗
04Train and evaluate.

Use generated RGB episodes for downstream policy training. Fixed initial states and task-specific metrics support comparisons across data sources and policy models.

Evaluation protocols ↗

03 / ACROSS EMBODIMENTS

Keep the manipulation.
Change the robot.

Retarget recorded trajectories to compatible robot kinematics and workspaces. These matched replays show the same garment and shared visual layout across five robot models.

Beyond a replay.

A separate UR5e experiment trains a policy from retargeted trajectories without new human demonstrations. Continuous flatten-to-fold execution remains challenging.

05 / THE METHOD

A learned data generator.

Human demonstrations and corrections train a NOCS-guided policy. Mirror augmentation expands supervision; task metrics select successful trajectories for re-rendering and RGB-policy learning.
